Biologics Intelligence: Citation-Verified Research Assistant FLAGSHIPLIVE
The problem. A consultancy in the spinal biologics market answered client questions such as "which of these 49 products are cleared as 510(k), PMA, or 361 HCT/P, and since when?" by reading FDA records, trial registries, journals, and SEC filings by hand. Days per question, and no way to show where each fact came from.
What I built, as sole engineer from first commit to production handover. A research assistant that answers such questions in about 2 minutes for about $1 of model spend, with every sentence tied to a passage the reviewer can open. The ingestion pipeline keeps a library current from five public sources (FDA 510(k)/PMA/openFDA, ClinicalTrials.gov, PubMed and PMC, SEC EDGAR, DailyMed) plus uploads: PDF parsing with GROBID, chunking, embedding, and product and company entity resolution across 33,800 documents, 668,000 passages, and 711 tracked products. Retrieval runs three lanes (vector, keyword, and sentence windows that surface one decisive sentence buried in boilerplate) merged by rank fusion over a pgvectorscale DiskANN filtered index. A five-stage LangGraph workflow then plans the searches, has a judge model read every candidate passage and keep only what supports an answer, writes, and checks each sentence against its citation before the reader sees it, refusing when the corpus does not hold the answer.
Results. A hard question went from 6 minutes and $4 to 2 minutes and $1 after retrieval and judge optimisation (filtered index, judging during retrieval, a small judge model on a fast host with fallback). On the client acceptance set, every regulatory number in the answers was verified correct against the FDA record. Each answer ships with a live progress view, a source panel per citation, an audit trail of what was searched and kept, and its cost. Delivered with an admin console (product registry, source schedules, user approval, per-stage model and reasoning settings, cost reporting), scheduled backups, and a full operations runbook, administrator guide, illustrated user guide, and cost sheet for handover.
Python · FastAPI · LangGraph · PostgreSQL 16 + pgvector + pgvectorscale · SQLAlchemy 2.0 (async) · Alembic · Celery + Redis · Next.js 15 · TypeScript · Tailwind v4 · OpenRouter (GPT-5.5, gpt-oss-20b on Groq) · GROBID · Docker · Railway · GitHub Actions

Omvi William — Multi-Tenant Agentic AI SaaS with Real-Time Voice FLAGSHIPDEMO
Designed and built end to end a white-labelled, multi-tenant AI SaaS for a telecom operator (World Mobile). Users talk or type to "William," which answers from the company knowledge base, acts in email and calendar, remembers earlier conversations, and turns a voice call into a project that a team of AI agents completes live. Architected six services around one agent brain: a FastAPI gateway that every chat and voice request passes through (Redis sessions and history, SSE streaming, LangGraph onboarding flows with human-in-the-loop pauses); a standalone LangGraph graph server so the agent ships independently of the API; a LiveKit voice worker; a pgvector RAG service with neighbouring-passage context; a multi-agent orchestrator; and a Next.js studio.
Agentic core: the LangGraph agent classifies every message and routes it to dedicated email and calendar orchestrators, knowledge-base search, cross-session memory recall with safeguards against fabricated recall, or a tool-calling responder (knowledge, web search, time, task creation), streaming tokens as they are generated, including the RAG answer stream relayed through the graph. Tasks extracted from each call run through five specialised agents (research, plan, build, review, write-up) with live WebSocket progress, per-agent output and token cost, instruction-driven re-runs, and downloadable reports. Voice: built the real-time voice agent (LiveKit Agents, Deepgram speech-to-text, Cartesia text-to-speech, Silero VAD, noise cancellation) on the same brain as chat, patching the LangChain adapter so the graph controls what is spoken; clear product questions go straight to retrieval behind an instant spoken filler, warm workers let the agent join a call in about 10 s, and each call's transcript becomes a titled session of linked tasks.
Knowledge and models: pgvector RAG with neighbouring-passage context and multilingual retrieval; every model routed through OpenRouter with automatic fallbacks and per-provider token and latency tracking; token streaming fixed for LangGraph on Python 3.10, cutting the first chat reply from 35 s to under 10 s. Platform: designed and implemented the multi-tenancy model (organization-scoped state, role-to-scope RBAC, scope-filtered tool binding) and authored the architecture plans the team adopted for serving many clients from one codebase, so a new client is configuration rather than a fork. Shipped to GCP through GitHub Actions and later as 8 services on Railway with auto-deploy from main and Playwright-verified releases.
